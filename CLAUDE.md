# CLAUDE.md

cda_jepa is the JEPA encoder for gym-continuousDoubleAuction, as an installable extension: the
encoder (`cda_jepa/encoder.py`), its RLModule and Learner (`cda_jepa/learner.py`) and an offline
pretrainer (`cda_jepa/pretrain/`). gym-CDA finds it through the `gym_cda.encoders` and
`gym_cda.extensions` entry points. Documentation is in `docs/` (start at `docs/README.md`).

## Rules

1. **The forks are never edited.** `third_party/ijepa` and `third_party/lejepa` are pinned
   submodules installed byte for byte (`tests/test_packaging.py`). Change a pin, not a file.
2. **Run `python -m pytest -q`**, then `ruff check .` and `ruff format --check .`. CI runs only
   pytest today (the ruff steps wait on a push with the `workflow` scope, #18), so the ruff pair
   is yours to run. Setup: skill `jepa-dev-setup`.
3. **Test first, and show it failing** on the previous source (`git stash push -- cda_jepa`,
   run, `git stash pop`).
4. **Do not rest a claim on a review.** Reproduce it in a scratch script first, and run the case
   that should pass beside it.
5. **Reviews file, they do not fix.** Each confirmed finding is a GitHub issue with a severity
   (`S1-blocking` to `S4-minor`), a kind (`bug`, `enhancement`, `documentation`, `test-gap`,
   `refactor`), an issue type (Bug, Task or Feature), and `agent` or `human`. An issue that needs
   both is split into sub-issues, each labelled. The issue footer is
   `_Generated by [Claude Code](https://claude.ai/code)_`.
6. **Test this package, not gym-CDA.** A test belongs here only if it fails when this package's
   code is wrong. Behaviour of gym-CDA's registry, catalog, probe split or checkpoint format is
   gym-CDA's to test.
7. **The changelog records what was true.** Add to `CHANGELOG.md` under Unreleased; do not
   rewrite released entries.

## Facts worth not re-deriving

- Build the encoder under `conftest.JEPA`, not `"jepa"`: on gym-CDA 2.2 the name is `_jepa_ext`.
- Mask sampling has its own generator; `torch.manual_seed` does not pin a mask once one is drawn.
  Set `encoder._mask_generator` instead.
- Only the actor's sub-encoder runs the objective (`JEPARLModule.setup`); `compute_values` turns
  it off so the value pass takes no EMA step.
- `jepa_latent_std` is the across-batch spread per masked position, so it sees a blind trunk (#4);
  after changing `_jepa_loss`, check it with skill `jepa-collapse-check`.
